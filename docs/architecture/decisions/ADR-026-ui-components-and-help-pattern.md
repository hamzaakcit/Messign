# ADR-026: One UI component set and one help pattern for marketing and engage

- **Status:** Proposed (2026-11-24, UX track Phase 2). The master prompt named this ADR-010; that number is taken by the migration baseline, so it is 026.
- **Context:** Marketing (`client/src/pages/marketing`) and engage (`client/src/engage`) now share one page (ADR-016). They draw controls three ways: `components/ui`, marketing-local copies (`components/bento`, `cockpit/*`, most deleted in UX-01), and inline Tailwind. Explanatory text is scattered across components. The copy audit found about 535 words on reachable marketing screens, much of it developer notes. Colour classes `text-app` and `bg-app` resolve to no CSS anywhere in the app.
- **Decision:**
  1. **Location.** Shared components stay in `client/src/components/ui`. No new `client/src/ui/` folder: a second set next to the existing one is the duplication this track removes. Marketing-local wrappers are allowed only for layout (`ViewportWrapper`).
  2. **Set.** Reuse what exists: `Button`, `Badge`, `Card`, `DataTable`, `EmptyState`, `ErrorState`, `Modal`/`dialog` (confirmations only), `SlideOverPanel`, `Tabs`, `InfoTooltip`. Add `HelpDrawer` (a `SlideOverPanel` that renders a registry entry) and `OverflowMenu` (`⋯` for secondary actions). Add `PageHeader` only when a second screen needs it.
  3. **InfoTip.** `InfoTooltip` gains a tap toggle, Escape to close, an `aria-describedby` link to its label, and an optional `helpId` that adds a "Learn more" link opening the HelpDrawer. Content is a string of one sentence, ≤ 120 characters; a unit test fails otherwise.
  4. **Help registry.** `client/src/lib/helpContent.ts` exports `HELP: Record<HelpId, { title: string; tip: string; body?: string }>`. `tip` is the InfoTip sentence; `body` is the HelpDrawer text. Components refer to an id, never to inline prose. A test checks every `tip` is one sentence ≤ 120 characters and every `helpId` used in source exists.
  5. **Empty states.** `EmptyState` with one sentence and one action. Not shown once data exists.
  6. **Colour.** Only defined tokens (`text-app-text`, `text-app-muted`, `bg-app-bg`, `bg-app-card`, `border-app-border`). A test fails on bare `text-app` / `bg-app` under `pages/marketing` and `engage`. The app-wide fix (908 occurrences in 160 files, 104 of them in marketing and engage) is separate work.
  7. **Engage screens** (roadmap WP-19/20/22 are done) adopt the set when touched; no rewrite for its own sake.
- **Consequences:** + one place to change help text, testable text budget, no invisible colour classes in the kept rooms. − `InfoTooltip` changes affect its two existing callers, both Company-OS (`ProjectMarketplaceAdmin`, `TaskColumn`); new props are optional so they keep working. − Engage components keep their own styling until they are next changed.
- **Rejected:** a new `client/src/ui/` folder (duplicates `components/ui`); a third-party tooltip library (the portal-based `InfoTooltip` already handles clipping); i18n-style keys for every label (labels are not explanations; only help text moves to the registry).
