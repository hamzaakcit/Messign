# ADR-016: The Company-OS Lucy page and engage are one page; the signed-in organization decides what is on it

- **Status:** Accepted (2026-11-10, after ADR-015)
- **Context:** ADR-015 put the engage screens on the Lucy page (`/marketing`), but only where engage runs alone: on the engage surface the page is the engage hub, and on the workspace or `all` surface it was still the Company-OS Lucy page with no engage in it. The platform owner uses the Company-OS Lucy page every day and wants customers, journeys, segments and templates on that same page, not on a second page. Engage access is decided per organization (`organizations.product`, `requireEngageUser`), and a Messign employee's organization is `workspace`, so the engage API refused them.
- **Decision:**
  1. **Product `all`.** Migration 126 widens the `organizations_product_check` constraint to `workspace`, `engage` and `all`. `all` means the organization may use the Company-OS modules and engage. `requireEngageUser` accepts `engage` and `all`; an unknown value, and `workspace`, are still refused (403). `GET /api/engage/me` now also reports the organization's `product`.
  2. **Only an operator sets it, and only for the platform organization.** `npm run engage:platform` sets product `all` for the organization named by `PLATFORM_ORG_SLUG` (default `messign`) and creates its engage settings row (sending stays disabled); `-- --off` sets `workspace` again. It refuses an engage tenant and any organization that does not exist. Applying the migration changes no organization, so production is unchanged until an operator runs the command.
  3. **One `/marketing` page, chosen by organization** (`client/src/engage/MarketingEntry.tsx`):
     - engage surface: the engage page (ADR-015), as before;
     - workspace surface: the Company-OS Lucy page exactly as it was; the engage API is not mounted there, so nothing is asked;
     - `all` surface: the client asks `GET /api/engage/me` and shows nothing until it answers. A tenant (`engage`) gets the engage page alone, never the Company-OS Lucy chat or tools (frozen for tenants, ADR-009, and their API is not tenant-safe). The platform organization (`all`) gets the Lucy page with the engage sections on it. An organization the engage API refuses gets the Lucy page as it was.
  4. **What the merged page holds:** the tabs Lucy (the chat), Customers, Journeys, Segments and Templates in the main area; the engage "Go to" tiles and quick actions in the CMO column next to Lucy's own; panels over the page for records and editors. The chat is hidden, not unmounted, while an engage tab is open, so it keeps its conversation.
  5. **Data stays per organization.** The platform organization is a tenant of its own in the engage tables (forced RLS by organization id); it sees none of the tenants' data and they see none of its data. Sending needs a channel account, readiness and `SEND_MODE` like any tenant (WP-22 for the screens).
  6. **Amends the "frozen modules" rule.** The Company-OS Lucy page is the host for the engage sections, so it takes that one change. Every other Company-OS feature stays frozen and behind `PRODUCT_SURFACE` / `VITE_PRODUCT_SURFACE`.
- **Consequences:** + one page for the platform owner, with tenant isolation unchanged; + nothing changes in production until the command is run; + a tenant on a shared deployment cannot reach the Company-OS Lucy page through `/marketing`. − the `all` surface still exposes the other Company-OS pages to anyone who signs in there (a tenant should sign in on an `engage` deployment); − the Lucy page now imports engage components, so the workspace bundle carries them; − `all` is meant for the platform organization only, and the command is the only guard (the database cannot tell which organization is the platform one).
- **Not in v1:** route guards for the other Company-OS pages by organization; a one-off "send now" action; engage AI (WP-23/24).
