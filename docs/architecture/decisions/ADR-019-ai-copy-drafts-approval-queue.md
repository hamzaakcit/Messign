# ADR-019: AI copy for a message step is a draft that passes gatekeepers and waits for a person; no profile data reaches a prompt

- **Status:** Accepted (2026-11-20, WP-24)
- **Context:** Tenants write the copy of journey messages by hand. The AI gateway (WP-23) can draft it, which is useful, but it is the riskiest AI write in the product: a draft could carry a customer's name or address into a prompt, or land in a template that a journey sends from. Principle 7 requires that AI may draft and never send, and that a person approves. Principle 3 requires that legal surfaces fail closed.
- **Decision:**
  1. **The drafting path reads no customer data.** It reads the journey definition (the message step's template key, purpose and pin, and the trigger's event name) and the template's existence. It never reads `engage.profiles`, identifiers, events, messages or any attribute. The prompt is built from fixed instructions, the step's purpose, the trigger's event name and the admin's brief. Nothing else.
  2. **The brief is screened.** It is the only free text that reaches a prompt. Email addresses, phone numbers (any form the profile normaliser accepts), Turkish IBANs, 11-digit national ids and Luhn-valid card numbers refuse the request before any model call. The refusal names the kinds, never the values. Names and street addresses have no reliable shape, so they are not detected: the design keeps them out of prompts instead (rule 1).
  3. **The whole prompt is screened again** just before the call, so a future change that adds a field cannot leak through this path silently.
  4. **The model is called through the gateway** (`generateText`, tier `complex`, which the gateway does not cache), metered per tenant by WP-23 with the monthly budget checked before the provider is contacted. A refusal by the budget answers 402 and stores nothing. No database transaction is open during the call.
  5. **The answer must be one JSON object** with a subject and an HTML or text body. Then the copy passes the gatekeepers: personal data in the output (by kind), the safe-variable and HTML rules of the template renderer (`checkTemplateContent`), a variable allowlist (`{{first_name | default: "..."}}` and, for marketing only, `{{unsubscribe_url}}`; no payload variables; every variable carries a fallback), the unsubscribe rule (marketing mail must have the link; transactional mail must not), no link or web address other than the unsubscribe placeholder (`link_not_allowed`), and no greeting word right before the first-name placeholder (`greeting_repeated`). The last two came from the first real-model check: the model wrote a placeholder shop address and a bare path, and repeated the greeting. Refusals return reason codes and store nothing.
  6. **What passes is a pending draft** (`engage.copy_drafts`, migration 129, forced RLS). Its content is fixed at insert; the database grants the engage role update rights on the decision columns only and no delete. A draft sends nothing and changes no message.
  7. **Approval adds a template version** through the template service, in the same transaction that locks and decides the draft. The template service runs its content checks again. Approval is once: a second decision returns 409. Admins decide; any tenant user reads the queue. Self-approval is allowed, as for journeys (D-13 open).
  8. **Nothing is pinned for the journey.** A step that pins a template version keeps that version; the new version reaches a step only where the step does not pin one. The draft response reports the pin, so the admin knows.
- **Consequences:** + no customer data reaches a model through this path, and a test plants a customer with name, email, phone and address and asserts none of it reaches the prompt; + a draft cannot reach a customer without a person approving it and the send gate still applying to every message; + one AI path, metered and budget-capped like the rest. − names and addresses typed by an admin into the brief are not caught by the screen (documented limit; the admin is the one typing them); − the copy is in the model's hands for quality: a bad draft is refused by the gate or rejected by a person, not prevented by design; − the queue is a panel under Templates, so the copy is read on screen before anyone approves it (see the follow-up entry in weekly progress).
- **Not in v1:** rewriting existing copy (the existing copy is not sent to the model, so no template content is in a prompt), per-language quality checks, a second approver (D-13), a list of brand words the copy must avoid.
