# ADR-017: Engage tenants are refused by default on every Company-OS route, socket and file download

- **Status:** Accepted (2026-11-10, found while closing the open items of ADR-016)
- **Context:** Probing a tenant's token against a server showed that `GET /api/users` answered 200 with all 13 Messign employee records, on an `engage` deployment as well as on `all`. `/api/users`, `/api/admin`, `/api/ai/actions` and `/api/notifications` are mounted on every surface, and the Company-OS routers were written for one organization (the default one): they answer from it whoever calls. Tenants' sockets also received Messign's presence, activity and task broadcasts, because the socket handshake never looked at the organization. On the `all` surface the same token also read projects, tasks, badges, the leaderboard and the dashboard. Fixing each route one by one would leave the next route that is added open again.
- **Decision:**
  1. **One guard, deny by default** (`server/src/middleware/tenantGuard.ts`), mounted on `/api` right after the token is read and before any router. A request whose verified token names an organization with product `engage` (a tenant) may reach only `/api/auth` (sign-in and session), `/api/engage` (which authenticates itself) and `/api/health`. Everything else answers 403 `Not available for this organization`, including routes that do not exist yet.
  2. **Who is a tenant** is read from `organizations.product` for the token's organization claim and cached for 30 seconds. A token with no claim, an unknown organization, `workspace` and `all` (the platform organization) are not tenants and are unchanged. If the product cannot be read, the request is refused with 503 (closed, not open), except on the allowed paths, which never need the lookup.
  3. **Odd paths never count as allowed:** dot segments, doubled or encoded slashes and backslashes fall through to the tenant check, and prefixes match on whole segments, case-insensitively as Express routes them.
  4. **Sockets and files:** the Socket.IO handshake and the production `/uploads` download refuse a tenant's token with the same check.
  5. **The client follows** (`SurfaceGate`, the session surface in `productSurface.ts`): on a shared (`all`) build the engage API says whether the user's organization is a tenant, and the app is drawn only after that answer. A tenant session is narrowed to the `engage` surface: engage pages only, no Company-OS requests, no Company-OS socket. The narrowing can only go from `all` to `engage`, never wider, and is undone on sign-out.
  6. A test reads `index.ts` and fails if a router is mounted on `/api` before the guard.
- **Consequences:** + a tenant cannot read Company-OS data on any surface, now or through a route added later; + the `all` surface is safe for tenants as well as for the platform organization (ADR-016's "tenants should use an engage deployment" is no longer a security requirement); + the engage-only pages need no change. − one cached lookup per tenant request outside the allowed paths (30 s staleness: a product change takes up to 30 s to apply); − anything a tenant legitimately needs outside `/api/auth` and `/api/engage` has to be added to the allow-list on purpose.
- **Not in v1:** rate limits per tenant on the allowed paths beyond the existing limiters; tenant-aware versions of the Company-OS routes (they stay closed to tenants).
