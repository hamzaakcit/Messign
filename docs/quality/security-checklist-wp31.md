# Security checklist (WP-31)

**As of:** 2026-11-24 (second pass), commit of the WP-31 PR. Scope from the backlog row: seed routes, rate limits, engage audit hash chain, dependency audit, CSP, secrets scan. Every item below was checked against the code of this branch, not against the roadmap text (the roadmap was partly stale: `/api/seed/*` still existed, and the `x-user-id` header path was already gone).

**How to read it.** *Closed* = fixed by code in this PR or earlier, with a test or CI step named. *Accepted* = a residual risk, stated with its reason and a trigger for revisiting it; it becomes accepted when Hamza ticks it in section 6 at merge. *Yours* = an action only Hamza can take (production access, browser check, legal). Nothing here is a compliance claim: these are technical controls. What the law asks of Messign and of tenants is in `docs/compliance/tr-messaging-obligations.md` and stays **requires legal confirmation [LC]**.

**What can be re-run.** `npm run security:secrets` (files) and `npm run security:secrets -- --history` (every commit), `npm run security:audit` (production dependencies), `npm run engage:audit-verify -- --all` (audit chains), `scripts/smoke-production.sh <api url>` (the deployed API), and the test suites named below. The first three run in CI on every push (job **Security checks**).

| 1.3e | **Password change** | **Closed** | It already checked the current password, the policy and the history; it now also ends every other session of the account and, for an engage tenant, records it.
